# Запуск EMILIYA LIFE OS — подробно, с нуля

Инструкция рассчитана на то, что терминал ты видишь нечасто. Каждая команда
объяснена: что делает, сколько идёт, что должно появиться на экране.

Две части:

- **Часть 1** — запустить на своём компьютере (15 минут). Делать обязательно:
  так ты убедишься, что всё работает, до того как что-то оплачивать и настраивать.
- **Часть 2** — постоянный адрес в интернете (30 минут).

---

# Часть 1. Запуск на компьютере

## 1.1. Открыть терминал

**macOS:** Cmd + Пробел → набери `Терминал` → Enter.

**Windows:** кнопка Пуск → набери `PowerShell` → Enter.

Откроется чёрное или белое окно с текстовой строкой. Команды ниже нужно
копировать туда и нажимать Enter после каждой.

> Терминал не спрашивает подтверждений и не рисует кнопок. Если после команды
> ничего не произошло и появилась новая строка — значит всё прошло успешно.
> Молчание здесь означает «готово».

## 1.2. Проверить, что установлен Node.js

```bash
node -v
```

**Что должно появиться:** `v20.11.0`, `v22.14.0` или похожее — главное, число
после `v` не меньше 20.

**Если появилось `command not found` или версия меньше 20:**
зайди на [nodejs.org](https://nodejs.org), скачай кнопку **LTS**, установи,
**закрой терминал и открой заново**, проверь `node -v` ещё раз.

Заодно проверь git:

```bash
git --version
```

Должно быть `git version 2.x`. На macOS при первом запуске может выскочить окно
«установить инструменты разработчика» — согласись и подожди.
На Windows git ставится с [git-scm.com](https://git-scm.com).

## 1.3. Скачать проект

```bash
cd ~/Documents
git clone https://github.com/marketguruop/marketguruop.git
cd marketguruop
git checkout claude/emiliya-life-os-build-ikmidi
cd life-os
```

Разбор по строкам:

| Строка | Что делает |
|---|---|
| `cd ~/Documents` | переходит в папку «Документы» — проект появится там |
| `git clone …` | скачивает репозиторий с GitHub |
| `cd marketguruop` | заходит внутрь скачанной папки |
| `git checkout claude/…` | переключается на ветку с Life OS |
| `cd life-os` | заходит в папку приложения |

**Что должно появиться:** после `clone` — несколько строк про `Receiving objects`
и `done`. После `checkout` — `Switched to a new branch`.

Репозиторий публичный, пароль и токен не спросят.

> Если проект уже скачан раньше — вместо `git clone` сделай `cd` в папку и
> выполни `git fetch origin` и `git checkout claude/emiliya-life-os-build-ikmidi`.

## 1.4. Создать файл настроек

```bash
cp .env.example .env
```

Команда молча создаёт файл `.env` — там лежат настройки и пароли. Для локального
запуска править его не нужно, значений по умолчанию хватает.

Файл `.env` никогда не попадёт на GitHub: он в списке игнорируемых. Это
специально — в нём хранятся секреты.

## 1.5. Установить зависимости

```bash
npm install
```

Скачивает библиотеки, из которых собрано приложение. **Идёт 1–3 минуты**, бежит
много строк — это нормально.

**Что должно появиться в конце:** `added 380 packages in 45s` (число пакетов
может отличаться).

Строки со словом `warn` или `deprecated` — не ошибки, их можно игнорировать.
Ошибка выглядит как `npm ERR!`.

## 1.6. Создать базу данных

```bash
npm run setup
```

Одна команда делает три вещи:

1. настраивает Prisma под локальную базу SQLite,
2. создаёт таблицы,
3. заполняет их тестовыми данными для демонстрации.

**Что должно появиться в конце:**

```
Seeding EMILIYA LIFE OS…
Готово. Вход: emiliya.shramkoo@gmail.com / lifeos123
```

Тестовые данные — это Bumble Coffee, Black Phoenix, Саша, счета и тренировки.
Они нужны, чтобы система не выглядела пустой. На постоянном адресе (Часть 2)
создаётся чистая система под твои настоящие проекты.

## 1.7. Запустить

```bash
npm run dev
```

**Что должно появиться:**

```
▲ Next.js 15.5.22
- Local:  http://localhost:3000
✓ Ready in 1.8s
```

Теперь открой браузер и зайди на **http://localhost:3000**

Вход: `emiliya.shramkoo@gmail.com`, пароль `lifeos123`

> Терминал теперь занят — он показывает работу сервера. Это правильно, не
> закрывай его. Чтобы остановить сервер, нажми в терминале **Ctrl + C**
> (именно Ctrl, даже на Mac). Чтобы запустить снова — снова `npm run dev`.

## 1.8. Что попробовать

1. **Дашборд.** Вверху — загрузка дня и три результата. Внизу поле быстрого
   ввода. Вставь туда:

   `Завтра написать Саше, договориться о съёмке и придумать три Reels; встреча с Cider House в четверг в 11`

   Нажми «Разобрать». Под полем появится список того, что создано: задачи,
   идея для контента и **запрос на подтверждение** для встречи.

2. **Подтверждения** (в меню слева). Там ждёт встреча из предыдущего шага, с
   превью: что будет создано и почему. Нажми «Подтвердить» — событие появится
   в календаре системы.

3. **Сегодня** → кнопка «Открыть мой день». Расписание с дорогой, подготовкой
   и резервными окнами. Справа — «Минимальная версия дня» на случай, когда сил мало.

4. **Задачи** — Kanban, таблица, поиск. Внизу — зависшие задачи и найденные дубли.

5. **AI Command Center** — список агентов, история запусков, стоимость.

### Проверить, что всё исправно

Останови сервер (Ctrl + C) и запусти:

```bash
npm run test
```

Должно закончиться строкой `Tests  85 passed (85)`.

# Часть 2. Постоянный адрес в интернете

Локальный запуск работает, только пока включён твой компьютер и запущен
терминал. Для постоянного доступа с телефона нужен хостинг.

Два бесплатных сервиса: **Neon** (база данных) и **Vercel** (приложение).
Для одного пользователя бесплатных тарифов хватает с запасом и они не истекают.

> Почему нельзя оставить ту же базу, что локально: SQLite — это файл на диске,
> а на Vercel диск стирается при каждом обновлении. Поэтому база отдельно.
> Схема изначально написана так, чтобы переезд был бесплатным по усилиям.

## 2.1. База данных — Neon

1. Открой [neon.tech](https://neon.tech) → **Sign up** → войди через GitHub.
2. **Create project**:
   - Name: `lifeos`
   - Region: **Europe (Frankfurt)** — ближе всего к Хельсинки
3. Откроется страница с блоком **Connection string**. Нужны **две** разные строки:

   **Первая — с пулом.** В выпадающем списке над строкой должно быть выбрано
   **Pooled connection**. В адресе будет кусок `-pooler`. Скопируй целиком:

   ```
   postgresql://neondb_owner:ПАРОЛЬ@ep-xxx-pooler.eu-central-1.aws.neon.tech/neondb?sslmode=require
   ```

   **Вторая — прямая.** Переключи список на **Direct connection**. Тот же адрес,
   но **без** `-pooler`. Тоже скопируй.

4. Сохрани обе строки в заметки — сейчас понадобятся.

**Зачем две.** Приложение на Vercel открывает много коротких соединений, для них
нужен пул. Но создание таблиц через пул не работает — для этого нужен прямой
адрес. Система подставляет нужный сама, если дать обе строки.

## 2.2. Приложение — Vercel

Всё делается из терминала, из той же папки `life-os`.

### Вход

```bash
npx vercel login
```

Спросит email, пришлёт письмо с подтверждением. Открой письмо, нажми ссылку,
вернись в терминал — там появится `Success!`.

> `npx` запускает программу без установки в систему — так не бывает проблем с
> правами доступа. При первом запуске спросит `Ok to proceed? (y)` — нажми `y` и Enter.

### Создать проект

```bash
npx vercel link
```

Ответы на вопросы:

| Вопрос | Ответ |
|---|---|
| `Set up "~/Documents/marketguruop/life-os"?` | `y` |
| `Which scope should contain your project?` | твой аккаунт (Enter) |
| `Link to existing project?` | `n` |
| `What's your project's name?` | `lifeos` (Enter) |
| `In which directory is your code located?` | `./` (просто Enter) |

Важно: команда запускается **из папки `life-os`**, поэтому корнем проекта
становится именно она, а не лендинги MarketGuru.

### Добавить настройки

Каждая команда спросит значение — вставляешь и жмёшь Enter. Затем спросит, для
каких окружений: стрелками и **пробелом** отметь **все три**
(Production, Preview, Development), потом Enter.

```bash
npx vercel env add DATABASE_URL
```
→ вставь строку **с пулом** из Neon

```bash
npx vercel env add DIRECT_DATABASE_URL
```
→ вставь **прямую** строку из Neon

```bash
npx vercel env add AUTH_SECRET
```
→ длинная случайная строка (ей подписываются входы в систему)

```bash
npx vercel env add SETUP_TOKEN
```
→ временный пароль, нужен один раз на шаге 2.3

Если своих случайных строк нет, сгенерируй:

```bash
# macOS / Linux
openssl rand -hex 32

# Windows PowerShell
-join ((1..64) | ForEach-Object { '{0:x}' -f (Get-Random -Max 16) })
```

### Выложить

```bash
npx vercel --prod
```

**Идёт 2–4 минуты.** В конце появится адрес вида
`https://lifeos-xxxx.vercel.app` — это твоё приложение.

Во время сборки система сама переключит базу на PostgreSQL и создаст таблицы.

### Проверить, что живо

```bash
curl https://ТВОЙ-АДРЕС.vercel.app/api/health
```

**Должно вернуться:**

```json
{"ok":true,"data":{"status":"up","integrations":{...}}}
```

Если вместо этого ошибка — дальше идти бессмысленно. Смотри логи:
vercel.com → твой проект → **Deployments** → верхний → **Building**.

### Дописать адрес в настройки

```bash
npx vercel env add APP_URL
```
→ вставь адрес, который выдал Vercel (например `https://lifeos-xxxx.vercel.app`)

```bash
npx vercel --prod
```

## 2.3. Создать свой аккаунт

База сейчас пустая — без тестовых данных, это твоя рабочая система. Аккаунт
создаётся одним запросом:

```bash
curl -X POST https://ТВОЙ-АДРЕС.vercel.app/api/setup \
  -H "content-type: application/json" \
  -H "x-setup-token: ТВОЙ-SETUP-TOKEN" \
  -d '{"email":"твой@email.com","password":"твой-пароль"}'
```

Пароль — минимум 8 символов. Подставь свои значения вместо заглавных букв.

**Должно вернуться:** `"createdUser": true`

Теперь заходи на свой адрес и логинься этой парой.

## 2.4. Закрыть дверь

Пока переменная `SETUP_TOKEN` существует, эндпоинт создания аккаунтов открыт.
Убери её:

```bash
npx vercel env rm SETUP_TOKEN
npx vercel --prod
```

После этого `/api/setup` отвечает 404 — создать второй аккаунт невозможно.

## 2.5. На домашний экран телефона

**iPhone / iPad:** открой адрес в Safari → кнопка «Поделиться» → **«На экран
"Домой"»**. Запустится без адресной строки, с нижней навигацией.

**Android:** Chrome → меню (три точки) → **«Установить приложение»**.

# Часть 3. Что подключить потом

Всё ниже — по желанию, система работает и без этого.

## AI-агенты

Без ключа Inbox Agent разбирает записи локальным парсером — работает, но проще.
С ключом включаются полноценные агенты.

1. [console.anthropic.com](https://console.anthropic.com) → **API Keys** → создать ключ
2. ```bash
   npx vercel env add ANTHROPIC_API_KEY
   npx vercel --prod
   ```

Лимиты расходов уже настроены: не больше 6 шагов и $1.5 на один запуск,
60 запусков в час. Видно на странице **AI Command Center**.

## Telegram — быстрый ввод голосом

1. В Telegram найди `@BotFather` → `/newbot` → придумай имя → скопируй токен
2. У `@userinfobot` узнай свой числовой id
3. ```bash
   npx vercel env add TELEGRAM_BOT_TOKEN        # токен от BotFather
   npx vercel env add TELEGRAM_WEBHOOK_SECRET   # любая случайная строка
   npx vercel env add TELEGRAM_ALLOWED_CHAT_ID  # твой id
   npx vercel --prod
   ```
4. Открой один раз в браузере (подставь свои значения):

   ```
   https://api.telegram.org/botТОКЕН/setWebhook?url=https://ТВОЙ-АДРЕС.vercel.app/api/telegram/webhook&secret_token=СЕКРЕТ
   ```

   Должно вернуться `{"ok":true}`.

Теперь работают `/today`, `/week`, `/add`, `/idea`, `/content`, `/done`,
`/energy`, `/inbox`, `/review`, `/approve`, `/cancel`. Обычное сообщение уходит
в Inbox Agent — надиктовал голосовое, Telegram расшифровал, система разобрала.

## Google Calendar

1. [console.cloud.google.com](https://console.cloud.google.com) → создать проект
2. **APIs & Services** → **Library** → найти **Google Calendar API** → **Enable**
3. **Credentials** → **Create Credentials** → **OAuth client ID** → тип **Web application**
4. В **Authorized redirect URIs** добавить:
   `https://ТВОЙ-АДРЕС.vercel.app/api/integrations/google/callback`
5. ```bash
   npx vercel env add GOOGLE_CLIENT_ID
   npx vercel env add GOOGLE_CLIENT_SECRET
   npx vercel env add GOOGLE_REDIRECT_URI   # тот же адрес callback
   npx vercel --prod
   ```
6. В приложении: **Настройки** → **Подключить Google Calendar**

# Часть 4. Если что-то пошло не так

| Что видишь | Что это | Что сделать |
|---|---|---|
| `command not found: node` | Node.js не установлен | Поставить с nodejs.org (LTS), перезапустить терминал |
| `command not found: git` | git не установлен | macOS: согласиться на установку инструментов. Windows: git-scm.com |
| `npm ERR! code EACCES` | нет прав на запись | Использовать `npx vercel` вместо установки глобально |
| `Port 3000 is in use` | порт занят другой программой | `npm run dev -- -p 3001`, открывать localhost:3001 |
| `Environment variable not found: DATABASE_URL` | нет файла `.env` | Выполнить `cp .env.example .env` в папке `life-os` |
| `P1001: Can't reach database server` | база недоступна | Проверить строку подключения из Neon; бесплатная база засыпает — повторить через 10 секунд |
| Сборка на Vercel падает на `prisma db push` | нет прямого адреса базы | Проверить, что `DIRECT_DATABASE_URL` добавлена и отмечена для всех окружений |
| `/api/setup` отвечает 404 | `SETUP_TOKEN` не задан | Так и задумано после шага 2.4. Если аккаунт ещё не создан — добавь переменную обратно |
| `/api/setup` отвечает 401 | неверный токен | Сверить `x-setup-token` со значением переменной |
| Страница белая, в консоли ошибки | сборка не доехала | vercel.com → Deployments → Runtime Logs |

Логи на Vercel: проект → **Deployments** → выбрать деплой → **Runtime Logs**.
Каждая строка — JSON; ошибки искать по `"level":"error"`.

Раз в месяц:

```bash
pg_dump "ПРЯМАЯ-СТРОКА-ИЗ-NEON" > lifeos-backup-$(date +%F).sql
```

Или в интерфейсе Neon: **Branches** → **Create branch** — мгновенный снимок,
из которого можно восстановиться.

## Посмотреть данные глазами

```bash
npx prisma studio
```

Откроет базу в браузере: таблицы, записи, можно править вручную.
Для локальной базы — просто так, для боевой — сначала
`export DATABASE_URL="прямая-строка-из-neon"`.
