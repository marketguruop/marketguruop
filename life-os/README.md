# EMILIYA LIFE OS

Персональная система управления: задачи, проекты, календарь, контент, деньги,
CRM, энергия — и несколько AI-агентов поверх всего этого, которыми управляет
центральный агент-координатор.

Ключевой принцип: **агент ничего необратимого не делает без подтверждения.**
Всё, что выходит наружу (календарь, сообщения, публикации, деньги), проходит
через Approval Center.

```bash
npm install

```

(меняется через `SEED_EMAIL` / `SEED_PASSWORD`).

переключается на локальный детерминированный парсер, а планировщик, проверки
качества и Approval Center работают всегда — они не используют модель вообще.

## Архитектура

```
Next.js 15 (App Router)  ──  UI + API routes в одном процессе
        │
        ├── src/lib/scheduling/   чистый планировщик и scoring (без I/O, покрыт тестами)
        ├── src/lib/ai/           агенты, промпты, память, лимиты, оркестратор
        ├── src/lib/approvals/    политика доступа и исполнение подтверждённых действий
        ├── src/lib/services/     доменные операции (задачи, план)
        ├── src/lib/integrations/ Google Calendar, Telegram
        └── Prisma → SQLite (dev) / PostgreSQL (prod)
```

### Почему так

- **Один Next.js вместо отдельного FastAPI.** Вся логика агентов — это
  оркестрация вызовов Anthropic API и запись в БД. Отдельный Python-процесс
  добавил бы точку отказа и деплой без выигрыша.
- **SQLite сейчас, PostgreSQL потом.** Схема написана Postgres-совместимо: нет
  нативных enum'ов, нет скалярных массивов, нет db-специфичных типов. Переход =
  смена `provider` + `DATABASE_URL` + `prisma db push`. `docker-compose.yml`
  с Postgres уже в репозитории.
- **Планировщик — чистая функция.** `planDay` / `planWeek` не ходят в базу и не
  читают часы: всё передаётся аргументами. Поэтому правила («не больше 75%»,
  «не больше трёх тяжёлых блоков подряд») проверяются тестами, а не на глаз.

## Агенты

Центральный агент (Chief of Staff) маршрутизирует запрос по ключевым словам —
детерминированно, без вызова модели: это мгновенно, бесплатно и не может
«придумать» не тот адресат.

| Агент | Режим | Что делает |
|---|---|---|
| Chief of Staff | пишет | План дня/недели, приоритеты, риски, итог |
| Inbox Agent | пишет | Разбирает хаос на задачи, события, идеи, контент |
| Calendar Agent | пишет | Окна, конфликты, дорога, подготовка, восстановление |
| Task & Project Manager | пишет | Дубли, следующие шаги, зависшие, делегирование |
| Review & Quality Agent | пишет | Проверяет остальных: дубли, конфликты, перегрузка |
| Content Director | советует | Контент-план, хуки, сценарии, shot list |
| Business & Marketing | советует | Проекты, ТЗ команде, отчёты, риски |
| Finance Agent | советует | Доход, счета, кассовые разрывы, подписки |
| Energy & Routine | советует | Сон, энергия, тренировки, минимальный день |
| Contacts & CRM | советует | Договорённости, follow-up, черновики |
| Automation Agent | советует | Повторяющиеся действия и сценарии автоматизации |

«Советует» = агент возвращает структурированный разбор и предложения, но не
пишет в базу сам. Так и задумано на этом этапе: сначала прочный фундамент из
пяти агентов, остальные подключаются по одному.

Системный промпт каждого агента лежит в отдельном файле: `src/lib/ai/prompts/`.

### Структурированный вывод

Агенты не возвращают свободный текст там, где ожидаются данные. Каждый ответ
ограничен JSON Schema на стороне API (`output_config.format`) и повторно
валидируется Zod-схемой перед использованием — `src/lib/ai/schemas.ts`.

### Лимиты

`AI_MAX_STEPS`, `AI_MAX_COST_USD_PER_RUN`, `AI_MAX_RUNS_PER_HOUR` — жёсткие
ограничители против бесконтрольных циклов. Каждый запуск пишется в `AgentRun`
со стоимостью и токенами; каждое действие — в `AgentAction`. Видно на `/agents`.

## Система подтверждений

| Уровень | Примеры | Поведение |
|---|---|---|
| SAFE | создать задачу, черновик, план, тайм-блок, объединить дубли | выполняется сразу, обратимо |
| CONFIRMATION | событие в календаре, сообщение, письмо, публикация, удаление, финансовая запись | preview → подтверждение в Approval Center |
| FORBIDDEN | переводы денег, пароли, настройки безопасности, массовое удаление | не выполняется вообще |

Неизвестное действие трактуется как CONFIRMATION (fail closed) — см.
`src/lib/approvals/policy.ts` и тесты `tests/approvals.test.ts`.

Удаления — мягкие (`deletedAt`), важные изменения пишутся в `AuditLog`.

## Планирование

Формула размещения задачи — `src/lib/scheduling/scoring.ts`. Веса в сумме дают
ровно 1 (проверяется тестом):

| Фактор | Вес | Фактор | Вес |
|---|---|---|---|
| срочность дедлайна | 0.24 | совпадение по энергии | 0.09 |
| приоритет | 0.18 | длительность | 0.05 |
| стратегическая ценность | 0.12 | разблокирует другие задачи | 0.05 |
| влияние на доход | 0.11 | совпадение по контексту | 0.04 |
| влияние на медиа | 0.07 | влияние на здоровье | 0.05 |

Плюс штраф за переносы: −0.05 за каждый, максимум 3. После третьего переноса
задача не переносится молча, а выносится на решение: удалить, делегировать или
переформулировать.

Ограничения планировщика (все покрыты тестами):
не больше 75% занятого времени · минимум 25% резерва · одна главная задача дня ·
максимум три результата · не больше трёх тяжёлых блоков подряд · зазор между
блоками · дорога, подготовка и восстановление вокруг событий · бег и тяжёлая
силовая не в один день · рабочие часы и сон.

## Таймзоны

Основная — `Europe/Helsinki`, но пользователь путешествует. Все `Date` внутри
системы — абсолютные моменты (UTC); «локальное» время всегда явное и считается
через `Intl` (`src/lib/dates.ts`). Тесты покрывают переход на летнее время
(23-часовой и 25-часовой день) и разные зоны.

## Интеграции

### Telegram

Заполни `TELEGRAM_BOT_TOKEN` и `TELEGRAM_WEBHOOK_SECRET`, затем:

```bash
curl "https://api.telegram.org/bot<TOKEN>/setWebhook?url=<APP_URL>/api/telegram/webhook&secret_token=<SECRET>"
```

Команды: `/today` `/week` `/add` `/idea` `/content` `/done` `/energy` `/inbox`
`/review` `/approve` `/cancel`. Обычное сообщение уходит в Inbox Agent — так же,
как быстрый ввод в вебе.

### Google Calendar

Заполни `GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`, затем
на `/settings` → «Подключить Google Calendar». Синхронизация читает все
выбранные календари, дедуплицирует по `externalId` и обрабатывает таймзоны.
Создание события в Google происходит только после подтверждения.

## Память

Три слоя (`src/lib/ai/memory.ts`):

- **short** — текущий диалог, держится вызывающей стороной;
- **working** — активная неделя: проекты, дедлайны, ожидаемые ответы. Считается
  из живых данных, поэтому не устаревает;
- **long** — цели, правила, предпочтения, паттерны. Строки в БД, которые можно
  посмотреть, изменить и удалить.

В промпт уходит не вся история, а только релевантное: `retrieveMemory` считает
пересечение по ключевым словам × вес, с гарантированным попаданием правил и целей.

Управление: `/settings`, `GET/POST /api/memory`, `DELETE /api/memory/<id>`,
`DELETE /api/memory?layer=long`.
